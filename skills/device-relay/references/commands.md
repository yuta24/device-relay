# Commands and options

| Command | Usage |
| --- | --- |
| `screenshot` | `relay screenshot [-o <file>\|-] [--format png\|jpeg] [--quality 0.05-1.0] [--max-size <px>] [--scale <px/pt>]`. Prints the saved file's absolute path as one line (default `$TMPDIR/relay/screenshot-<time>.png`). A `.jpg` / `.jpeg` extension or `--quality` selects JPEG (default quality 0.7). `--max-size` is the pixel count of the longer edge and `--scale` the upper limit of pixels per point; the device shrinks the image (with both, the smaller wins; it never enlarges). When shrunk, stderr gets the image size, the screen size, and px/pt ([Coordinates and orientation](coordinates.md)). `--scale 1` gives about 400×870 px on an iPhone (a full-resolution image is 1206×2622 px); on large screens such as an iPad, also add `--max-size 1024` |
| `source` | `relay source [--format json\|text\|compact] [--filter interactive] [--max-depth <n>] [--bundle-id <id>]`. `--max-depth 0` is the root only. `compact` is one element per line, and `--filter interactive` keeps only the elements you can operate ([Element tree formats](element-tree.md#element-tree-formats)) |
| `find` | `relay find <selector> [--limit 20] [--timeout <s>] [--gone] [--require] [--bundle-id <id>]`. `--limit` is 1–100 and `--timeout` up to 10 seconds. Each match has `type`, `identifier`, `label`, `value`, `frame`, `enabled`, and `index`. No match is exit code 0 (`"count":0`), or 6 with `--require`. For a wait longer than 10 seconds, repeat a short `--timeout`. `--gone` waits the other way, for no element to match ([Waiting for an element to go](clear-and-gone.md#waiting-for-an-element-to-go)) |
| `tap` | `relay tap (<x> <y> \| <selector>) [--mode private\|xcui] [--timeout <s>] [--bundle-id <id>]`. `--timeout` and `--bundle-id` apply to selectors only |
| `press` | `relay press (<x> <y> \| <selector>) [--duration 1.0] [--mode private\|xcui] [--timeout <s>] [--bundle-id <id>]` |
| `swipe` | `relay swipe <x1> <y1> <x2> <y2> [--duration 0.3] [--hold 0.05] [--mode private\|xcui]`. Holds at the start for `--hold` seconds, then moves to the end over `--duration` seconds |
| `type` | `relay type [--clear] [<text> \| --stdin] [--key return\|delete\|space]... [--bundle-id <id>]`. `--key` can repeat and is sent in order after the text. It doesn't return until typing finishes (about 15 ms per character on a simulator), and waits for the response up to 30 seconds + 0.1 seconds per character + 1 second per key. For text starting with `-`, put `--` first: `relay type -- -text`. Tap the text field first. `--clear` empties the field first, and with no text only empties it ([Clearing a field](clear-and-gone.md#clearing-a-field)) |
| `key` | `relay key return\|delete\|space [--bundle-id <id>]` |
| `button` | `relay button home\|volumeUp\|volumeDown` (volume buttons on physical devices only) |
| `orientation` | `relay orientation portrait\|portraitUpsideDown\|landscapeLeft\|landscapeRight\|landscape` (`landscape` is an alias for `landscapeLeft`) |
| `launch` / `terminate` | `relay launch <bundle-id>` / `relay terminate <bundle-id>`. They don't return until the app has launched or terminated, and wait for the response up to 150 seconds (30 + 120). For an app that isn't installed, `launch` sends nothing to the runner and exits 6 at once (`app_not_installed`). When it can't tell, it prints `cannot tell whether …` and sends it |
| `install` / `uninstall` | `relay install <APP.app\|APP.ipa> [--udid <udid>]` / `relay uninstall <bundle-id> [--udid <udid>]`. Puts an app on the runner's device (`--session`, `--runner` as for other commands) or on `--udid` (no runner needed), with `simctl` / `devicectl` on the Mac and not through the runner, and prints `{"ok":true,"app":{"bundleID":…,"name":…,"version":…},…}`. A simulator must be booted and a device connected (else exit 1, `device_unavailable`; relay doesn't boot it). Pick the build for the device: a simulator takes an `iphonesimulator` build (`…/Debug-iphonesimulator/<App>.app`), a device a signed `iphoneos` build or `.ipa`; the other kind is exit 1, `app_platform_mismatch`, nothing sent. Signing or provisioning errors: exit 1, `app_install_failed`, with `devicectl`'s reason in `error`. An installed app with the same bundle ID is replaced without asking; if it was running, it quits to the home screen, so `relay launch` it again (the runner keeps working; not checked on a physical device). `uninstall` of an app that isn't installed: exit 6, `app_not_installed`, nothing removed (fine when you only need it gone). The runner's own apps (`host`, `…RelayRunnerHost…`) are refused: exit 1, `app_uninstall_refused`. Removing an app deletes its data: on a physical device, ask the user first. Waits up to 300 seconds (install) / 60 (uninstall): the first install after a simulator boots took about 50 seconds, later ones under 1 second. Without an app, both still copy or delete the runner as `relay runner install` / `uninstall` do (a note on stderr) until the next release; use `relay runner …` for that |
| `open` | `relay open <url> [--bundle-id <id>]`. Opens a URL as tapping a link does, to go straight to a screen by deep link: `https://` in Safari, a custom scheme (`myapp://title/42`) in the app that registered it, launched if needed. `--bundle-id` sends the URL to that app whatever its scheme (an `https://` link to the app itself). Answers once that app is in front (up to 5 seconds) with `{"ok":true,"foreground":{"bundleId":…}}`; when the app already in front opens it, the whole 5 seconds pass unless `--bundle-id` names it. Quote and percent-encode the URL: a space or no scheme is exit 2. No app for the scheme: exit 6, `open_failed`. `--bundle-id` of an app not installed: exit 6, `app_not_installed`. Then check the screen with `relay find --id … --timeout 5 --require`. Checked on an iPhone 17 simulator (iOS 27.2) and an iPhone 14 Pro (iOS 26.7.1); a cold start came to the front within 1 second on the device |
| `foreground` | The foreground app's `bundleId` and `pid` |

- `relay shutdown` isn't in the list. Normally use `relay stop`. `shutdown` only sends `/shutdown` to the runner and returns at once with `{"ok":true}`; removing runner.json and shutting down the simulator is done a few seconds later by `relay start` when it sees the runner end (you can't tell when that is finished). If `relay start` is no longer running, runner.json stays behind. `relay stop` waits until the end and prints `stopped`.
- The wait for a response is 30 seconds plus how long that operation may wait (`--timeout`, `--duration`, `--hold`, `type` / `launch` / `terminate` above, 1 second for `key`). Make your own command's timeout longer than that. Even after a timeout (`no response within <seconds>s`, exit code 3) the runner keeps working on the operation, and other commands get 409 (exit code 5) until it finishes, so wait for `busy` in `relay ping` to become `false` before continuing. A `launch` timeout can last several minutes. `relay stop` works while busy, so if you started the runner yourself, stopping and restarting recovers faster.
- `--type` names, key names, button names, orientations, and numeric ranges are checked before sending; a wrong one is a usage error, exit code 2, and nothing is sent (for example `relay key tab` → `unsupported key 'tab'`).
- Don't normally give `--mode` (the default `private` is fast; `xcui` waits for the app to go idle, so each takes 1–2 seconds).
