# 既知の制約

現時点の device-relay の既知の制約です。全体の入口は [README](../README.md) です。

- **タッチ合成は非公開 API 依存**: `private` 経路は Xcode / iOS の更新でセレクタやシグネチャが変わると使えなくなります。消えた場合は自動で `xcui` に落ちますが、シグネチャだけ変わった場合は検出できません。表示の向きの取得（`interfaceOrientation`）も非公開 API で、使えない場合はスクリーンショットから求めるので遅くなります。
- **`xcui` 経路は遅い**: XCUI はイベントを送る前後に対象アプリがアイドルになる（quiescence）のを待つため、タップ 1 回にシミュレータの Safari で約 1.6 秒、実機の計算機で約 1.2 秒（以前の計測では約 1.9 秒）かかります。
- **`/type`・`/key`**: キーボードのフォーカスがある要素が必要です。対象は前面アプリで、`fallback`（非公開 API が使えない場合）では手で切り替えたアプリを判別できないので、`bundleId` を明示してください。`tab` と `escape` は iPhone で効かないため対応しておらず、400 になります（「[文字入力と特殊キー](http-api.md#文字入力と特殊キー)」）。
- **前面アプリの取得は非公開 API 依存**: `XCAXClient_iOS` などが変わると `fallback` に落ちます。`/health` も前面アプリを返すぶん遅くなりました（実機で p50 約 16 ms）。
- **映像ストリームはまだない**: 画面はスクリーンショットのポーリングで取得します（シミュレータの縦向きで png 約 90 ms / jpeg 約 110 ms、横向きは正規化のぶん遅くなります）。縮小（`maxSize` / `scale`）しても、XCUI の撮影自体（約 60 ms）は変わりません。
- **ローカルネットワーク許可**: 実機では初回にローカルネットワークの許可ダイアログが出ることがあります。
- **`/health` の画面サイズ**: xctrunner には起動画面の設定がないため、実機ではランナー内の `UIScreen` が 320×480 の互換モードになります。そのため `/health` は SpringBoard の frame から縦向きの画面サイズを、スクリーンショットのピクセル数から scale を求めます（初回だけ計測してキャッシュします）。向きはリクエストのたびに読み直して幅と高さに反映します。
- **`portraitUpsideDown`**: iPhone のアプリの多くは上下逆さに回転しないので、`/orientation portraitUpsideDown` の後も `/health` の `orientation` は直前の向きのままになることがあります。表示が逆さになった場合の座標変換は実装していますが、検証していません。
- **音量ボタン**: `volumeUp` / `volumeDown` は実機でのみ使えます（シミュレータでは 400）。
- **実機の `home`**: 実機では `XCUIDevice.press(.home)` が成功を返すのに何も起きません（iOS 26.7.1 + Xcode 27 で確認）。testmanagerd が `Failed to load displays from CADisplay` で画面を取得できず、ボタンのイベントを画面に結びつかないキーボードから送るため、SpringBoard が無視します。そのため実機の `/button home` は、ホームインジケーターのジェスチャー（画面下端から上への素早いスワイプ）で代用します。`private` 経路では 0.12 秒のスワイプ（約 0.35 秒で応答）、`private` が使えない場合は XCUI のドラッグ（最初に 0.02 秒押す必要があります。約 1.8 秒）です。ホームボタンのない端末が前提で、ホームボタンのある端末では同じジェスチャーでコントロールセンターが開きます。シミュレータでは `press(.home)` が効くので、そのまま使います。
- **要素セレクタ**: 完全一致だけです（「[要素セレクタ](elements.md#要素セレクタ)」）。キーボードやシートに隠れている要素も frame が画面内なら `offscreen` にならず、隠している側がタップされます（`isHittable` は見ていません。`/source?filter=interactive` はキーボードと手前のコントロールに隠れた要素を外しますが、近似です）。`timeout` は 1 回のスナップショットを中断できず、別プロセスのシート（設定の Apple Account のサインイン画面など）が出ている間は、XCTest のスナップショットが `Timed out while evaluating UI query` で失敗するまで約 3 分戻らないことがありました（`/source` も同じです）。その間は busy ゲートを持ったままなので、ほかのリクエストは `409` になります。また `/launch` の直後は前面アプリの取得が切り替え前のアプリを返すことがあるので、確実に対象を決めたい場合は `bundleId` を指定してください。
- **automation mode の有効化でパスコードを求められる**: XCTest は、テストを始める前に端末の testmanagerd が automation mode を有効にするのを `XCUIApplicationStateTimeout`（既定 60 秒）だけ待ちます。このとき端末にパスコード入力画面が出ることがあり、入力されるまで有効化は終わりません（iOS 26.7.1 + Xcode 27 で、有効化に約 53 秒かかった回や、60 秒を超えて `Timed out while enabling automation mode.` で失敗した回がありました）。いったん許可されるとしばらくは有効なようで、直後に起動し直すと有効化は数 ms で終わります。入力の時間を取るため、スキームのテストアクションで `-XCUIApplicationStateTimeout 120` をランナーに渡し、ランナーは有効化が終わったら非公開関数 `_XCTSetApplicationStateTimeout` で 60 秒に戻します（`/launch` や `/terminate` の待ち時間は変わりません。関数がなければ 120 秒のままです）。120 秒以内に入力されなければ時間切れになるので、端末でパスコードを入力してから `relay start` し直してください。この引数のない古いビルドを再利用すると、`relay start` が note を表示します。チェックアウトの Runner なら `relay start --rebuild` で作り直せば済みます。`relay install` で入れた Runner（`~/.relay/runner`。`--project` や `$RELAY_HOME` でそこを指定した場合も同じ）は `--rebuild` だけではコピー済みの古いスキームのままビルドされるので、note のとおり `relay install` をやり直してから `relay start --rebuild` してください。起動に失敗したときの hint は、実機の UI テスト初期化の失敗（`Failed to initialize for UI testing`）ならパスコードの入力、UI オートメーションの設定、ロック解除の順に、シミュレータでの同じ失敗なら「1 回だけ起動し直す」を表示します。`** TEST FAILED **` などテストの失敗では hint は出さず、ランナーのログのパスだけを示します。
- **表示が複数ある端末（iPhone Duo）**: Xcode 27.1 以上と iOS 27.1 以上の iPhone Duo が要ります（Xcode 27.2 と iOS 27.2 のシミュレータで確認。実機は未確認）。前面アプリの表示の判定、表示を指定した合成タッチ、要素の表示の ID はどれも非公開 API です（「[表示が複数ある端末](screen.md#表示が複数ある端末iphone-duo)」）。表示を指定できない Xcode では、`private` 経路を使わずに `xcui` に落ちます（`mode: private` の指定は 400）。折りたたみの切り替え（Closed・Book・Open）は relay からはできず、Xcode の DeviceHub の姿勢コントロールで行います。Closed から Open に切り替えると、シミュレータが起動し直してランナーが止まることがあり、そのときは `relay start` し直します。`/orientation` は Duo では画面を回転させません（外側は portrait、内側は landscapeRight のまま。`/health` の `orientation` は実際の向きを返します）。Xcode 27.2 の `xcrun devicectl device orientation set` / `rotate` も、Duo では成功を返すのに `get` が portrait のままで、画面は回転しませんでした（iPhone 17 Pro シミュレータでは回転します）。内側では、SpringBoard が前面のときと、回転しないアプリが前面のときに `xcui` の座標タッチが届かないので `422` にします（回転しないアプリの判定は window が縦向きかどうかによるもので、その状態では確かめていません。内側で起動した RelayRunnerHost が回転表示になったときは、window が横向きの形で (282, 0) から始まっていて、この判定には当たらず、window の原点からの差で送った `xcui` の座標タップ・要素タップが入力欄に届きました）。コマンドごとにアプリの表示を調べるので、`/health` などが遅くなります（設定アプリで約 0.15 秒、ホーム画面で約 0.4–0.5 秒）。折りたたみを何度か切り替えた後、ホーム画面のアイコンの一部で、SpringBoard が返す frame が画面上の位置と合わないことがありました（外側では Watch のアイコンが (145, 85) にあるのに frame が (52, 331)、内側では Settings のアイコンが (763, 385) にあるのに frame が (516, 287) で、要素指定のタップは成功を返して何も起きませんでした）。そのアイコンを要素で指定したタップは外れることがあるので、スクリーンショットで確かめてください。`/source?format=text` は表示の向きへの変換も、ほかの表示の window の除外もしません。
- **usbmux 非対応**: 実機への接続には CoreDevice トンネル（または `--allow-wifi` で Wi-Fi）が必要です。
- **通信は平文**: 認証はトークンだけで、TLS はありません（「[認証](http-api.md#認証)」の脅威モデルを参照）。`relay` を `kill -9` などで強制終了した場合は `~/.relay/runner.json` が残ります（サブコマンドは接続できずに終了コード 3、別のランナーが同じポートにいれば 4 になります）。
